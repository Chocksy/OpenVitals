iOS · second pass

Phase 36. A week on the phone found four things: the plan lists rows that cannot be ticked, Add says “Sending” and then shows nothing, the home markers are too big to reach and meals cannot be edited or deleted. This page redraws the phone around those four, at the density of the apps the owner actually uses, in our own colours. Nothing on file is dropped — the goals, the sentence, the systems, the markers with their ruler and sparkline, the plan rows with their basis labels and aims, the meals with the estimate flag, the Apple Health rows, the research rows and the receipt chips are all still here. They are rearranged, sized and animated.

Everything on this page moves on its own. The scan line sweeps, the shimmer runs, the loader thinks, the kept words fade in one at a time, the ring fills and the tick draws itself. Section 08 states each of those as a duration, an easing and a trigger so the Swift build copies rather than guesses.

08

Motion

Every moving thing on this page, stated so the Swift build copies it. The easing is the system's one curve, cubic-bezier(0.22, 1, 0.36, 1), unless the row says otherwise. Nothing loops except the three states that are genuinely waiting on a network call.

What moves Element Duration Easing Trigger
The scan line ScanOverlay 2 200 ms, loops system ease the photo is uploaded; stops when the vision call returns
The shimmer ScanOverlay 2 200 ms, loops linear same as the scan line, under it
The three dots ReadingLoader 1 200 ms, loops · 150 ms apart system ease Send is pressed, on both the text and the photo path
A kept word arrives chip · .chipin 500 ms, 460 ms apart system ease each chip the reader returns, in the order it returns them
A callout arrives Callout 420 ms, 520 ms apart system ease the vision call returns items; one per item
The meal card rises MealCard 400 ms · 21 px system ease the server total is accepted
The ring fills ProgressRing 900 ms, 300 ms delay system ease Today appears, and again on every tick
The chip presses MoveChip 320 ms · 0.96 → 1.03 → 1 system ease tap down
The check draws in MoveChip · stroke-dashoffset 400 ms, 120 ms delay system ease the tick write is accepted, never before it
The ring segment flashes lime ProgressRing 250 ms in, 400 ms out system ease the same accepted write, once
The flame breathes StreakFlame 2 400 ms, loops system ease the streak is one day or more; still when it is zero
The tooltip appears ChartTooltip 150 ms system ease finger down on the plot; follows the finger with no animation
The swipe reveals SwipeRow tracks the finger · 250 ms to settle system ease a horizontal drag past 34 px
The range changes RangePills 250 ms system ease a pill is tapped; the pill slides, the line redraws

Reduced motion. One variant covers all of it: every looping animation stops and shows its end state, the check appears already drawn, chips and callouts appear at full opacity with no offset, the ring is drawn filled, and the meal card and the tooltip cross-fade instead of translating. Nothing is removed and no information is lost, because none of these animations carry information the text does not already carry.

Build cost

Exists today. The write path, unchanged. POST /api/sync/healthkit takes up to 20 000 samples and maps 27 types onto readings, daily logs and profile facts. POST /api/capture does the hard half of the Add flow: it takes the photo, classifies it, extracts per-item macros, sums them on the server with a clamp, and returns chips with an estimated flag. POST /api/habits is one tick per item per day. Auth is a session cookie the Swift client adopts by hand.

Does not exist, and this pass depends on it. One: a meals table (userId, at, photoKey, items jsonb, kcal, proteinG, carbsG, fatG, estimated, tickedItemId) plus file storage for the photograph. Without it there is no meal detail, no edit, no delete and no thumbnail — the three things the owner asked for are all one table away. Two: a streaming capture route, so the chips arrive one at a time. The design will still work without it — the loader runs and all five chips land together — but the four seconds stay opaque. Three: DELETE /api/capture/:id, because the receipt offers Undo. Four: the Plan split. /api/plan/today must return adopted and suggested as two lists with the duplicates already collapsed, and /api/plan/adopt must turn a suggestion into a habit with a schedule. Until then the phone cannot honestly hide a tick box, because it cannot tell the two kinds apart. Five: the workouts half of the HealthKit sync, which is why three real sessions never ticked the exercise chip. That is an engine fix; the drawing only shows what it looks like when it works.

What the phone must gain. Nine components, of which four carry the animation: MoveChip, ProgressRing, ReadingLoader and ScanOverlay. Two gestures that do not exist today: the horizontal swipe on a meal row, and the drag on the trends chart. One rule written into the view model rather than the view — a row without a habit id cannot render a tick box — so the bug the owner found cannot come back in a different screen.
